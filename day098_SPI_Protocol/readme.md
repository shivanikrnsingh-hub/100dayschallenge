## **Day 098: Serial Peripheral Interface (SPI) Master-Slave Bus Controller**

### **Description**
This project implements a complete synchronous **Serial Peripheral Interface (SPI) Protocol Loopback System** comprising a dedicated SPI Master controller and an SPI Slave peripheral. SPI is a synchronous, full-duplex, 4-wire serial communication bus standard commonly used for short-distance data exchange between microcontrollers and peripheral ICs.

The system features an independent clock-divider network built into the Master FSM that fractions down the main system clock (`clk`) into a specialized serial clock channel (`sclk`). The Master parallelizes and serially shifts out transmit words (`tx_data`) bit-by-bit via the Master-Out-Slave-In (`mosi`) wire, while the Slave samples the active serial stream and pieces it back together into a parallel output byte (`rx_data`).

---

### **Hardware Architecture**
The architecture maps its logic across distinct structural blocks connected via standard serial link boundaries:

* **SPI Master Module:** Operates using a 3-state finite state machine (`Idle`, `Trans`, `Finish`).
  * **Clock Divider (`clk_div`):** Generates `sclk` from `clk` by toggling every 5 cycles (`if(clk_div==4)`), yielding an explicit clock division factor of 10.
  * **Shift Register (`shift_reg`):** Captures parallel `tx_data` when the `start` strobe hits, and streams it out Most Significant Bit (MSB) first via `mosi` on successive shifting loops.
* **SPI Slave Module:** Driven directly by the serial clock line (`sclk`) generated by the Master module.
  * **Chip Select Watchdog:** Uses the active-low chip select input (`cs_n`) as an asynchronous clear. If `cs_n` is driven high, the internal bit tracking counters and shift memories are instantly flushed.
  * **Deserialization Register:** Shifts incoming bits into a parallel format and flashes the `data_ready` notification flag once an entire 8-bit frame has been captured.

---

### **SPI Bus Line Interface Matrix**

| Pin Node Name | Direction (Master perspective) | System Functionality | Hardware Behavior |
| :---: | :---: | :--- | :--- |
| **`cs_n`** | **Output** | Active-Low Chip Select | Driven Low to initiate communication and wake the Slave peripheral. |
| **`sclk`** | **Output** | Serial Clock | Generated by Master clock-divider loop; defines the protocol data rate. |
| **`mosi`** | **Output** | Master-Out Slave-In | Main single-ended transmit lane conveying serial data bits downstream. |
| **`done`** | **Output** | Internal Done Flag | Asserted High to inform the host microcontroller that the transfer is complete. |

---

### **Technical Implementation Details**
* **SPI Mode Configuration:** The system operates under standard **SPI Mode 0** mechanics ($\text{CPOL}=0$, $\text{CPHA}=0$). The serial clock `sclk` rests at zero (`0`) during `Idle`, data is sampled on the rising edge of `sclk`, and data shifts out on the falling edge of `sclk`.
* **Zero-Interruption Multi-Byte Frames:** The Slave deserializer bypasses temporary storage registers by shifting raw input directly into the destination array buffer (`rx_data <= {shift_reg[6:0], mosi};`) precisely at the 7th indexed bit boundary, reducing latency overhead.
* **Race-Condition Safe Interlocks:** The master state changes smoothly through internal synchronization (`state <= Finish`), preventing partial shifting loops or truncated frames.

---

### **Applications**
* **Sensor Bus Systems:** Communicating with digital chip accelerometers, gyroscopes, and temperature monitors.
* **Memory Card Interfaces:** Interfacing directly with SD cards and serial Flash/EEPROM storage devices.
* **Display Drivers:** Streaming configuration command registers and pixel data arrays to low-pin-count LCD or OLED display modules.

---

### **Verification & Testbench Summary**
The testbench (`spi_master_tb`) builds a complete simulation closed-loop by wiring the SPI Master ports straight into the matching SPI Slave ports:
1. **Reset Stabilization:** Asserts an early active-low reset pulse to clear all target logic layers uniformly.
2. **First Byte Frame Transfer:** Loads a hexadecimal value of `8'h3a` (`8'b00111010`) into the transmitter, fires the `start` pulse, and uses the `wait(done)` block to hold execution until the serial sequence completes.
3. **Second Byte Frame Transfer:** Loads a secondary pattern of `8'h56` (`8'b01010110`), executes a transmission run, and outputs the results to the display console.
4. **Console Output Reports:** Monitors tracking transactions to confirm loopback consistency using explicit `$display` diagnostics.
